# DesignLab 对话填写入口

2026-10-09。只搭建对话、演出与触发接口；台词及引导措辞由作者设计。五份序列的 `lines` 均保持空数组，未提供剧情草稿、默认台词或占位对白。

## 填写流程

1. 在 Unity Project 面板打开 `Assets/ScriptableObjects/Dialogue`，选择对应 `DL_*.asset`。
2. 保持 `sequenceId` 稳定，在 `Lines` 数组中新增条目，逐条填写 `speaker`、`text`，并按需要指定 `portrait` Sprite。条目顺序就是播放顺序。
3. 在对应 DesignLab 场景 Hierarchy 中找到 `DialogueCue_<sequenceId>`，检查关联的序列、触发范围与演出目标。场景引用同一份序列，修改台词不需要修改脚本或重新组装关卡。
4. 单独打开这一份实验场景进行 Play Mode 检查；在进入触发范围前、对话中、关闭后分别确认显示、输入和世界状态。作者确认台词后，再记录实际检查结果。

空序列用于保留填写入口，应保持静默：不得显示空对话框、暂停关卡、禁用玩家控制或播放引导演出。检查系统行为时使用独立的测试数据，检查结束后确认五份作者序列仍为空。

播放时按 Enter／E 或点击「继续」：当前文字尚未显示完时先全部显示，再次操作进入下一句。按 Tab 或点击「跳过」结束本段。空白条目不播放。关闭后下一帧恢复角色控制，避免推进对话时同时产生移动或攻击。正文区域以 1280×720 参考尺寸显示，长段落应分成多条，在填写后实际检查换行与溢出。

选中场景中的节点可见触发范围 Gizmo。默认 `oncePerScene` 为真，Retry 不重复播放已读段落；重新开始 Play Mode 会重新允许播放。关闭此选项后，角色必须先离开区域，再次进入才重新触发。`triggerAfterEncounter` 为真时，必须同时满足指定遭遇已完成、位置范围及落地条件。目标高亮只标示指定 Transform 所在位置，不改变目标本身的启用或碰撞状态。

## 数据与职责

- `DialogueSequence` 保存稳定 ID 和有序台词条目。当前五份 `lines: []`。
- `DesignLabDialogueCue` 保存角色、序列、位置范围、可选遭遇完成条件及可选演出目标。`triggerAfterEncounter` 为真时关联指定遭遇；完成节点如何组合范围与完成状态，以该组件的运行规则为准。
- 播放界面负责文字、头像、逐字／切页与关闭行为；台词数组不存放关卡奖励、存档或战斗参数。
- 演出目标引用已有封印或石台的 Transform；不修改目标的碰撞体、封印开门状态或美术导入设置。

## 检查记录边界

序列资产、场景引用与触发范围的静态检查不能证明对话 UI、文字可读性或真实玩家操作通过。运行检查至少覆盖空序列静默、作者台词的逐页显示、关闭后控制恢复、Retry 后节点行为、ESC 菜单协调，以及演出结束后已有物体状态恢复。正式台词验收等待作者填写。

## 第一段的制作与验收标准（2026-10-09）

优先用作者提供的 `DL_A_OPENING` 完成一次完整体验：安全进入 → 阅读／演出 → 推进或跳过 → 恢复操作 → 按引导完成作者指定的行动。正文和这段要表达的目标由作者决定；目前仍为空。验收通过后，再接封印前后的战斗与目标高亮。

| 项目 | 完成条件 | 当前证据与剩余检查 |
|---|---|---|
| 触发时机 | 落地且垂直运动稳定才播放；空文本、空中经过、死亡／结果 UI 和暂停时不误触发 | 技术条件已通过自动验证；真实入场与正常按键待测 |
| 可读与理解 | 原文、说话者、指定头像正确；实际换行无溢出、缺字或遮挡；未接受口头说明的试玩者能说出下一步行动 | 测试文字截图已检查；作者正文和玩家理解尚未验收 |
| 对话操作 | 推进先补全文字，再进下一句；跳过可结束；无漏句／重句；ESC 不叠加菜单 | 自动状态测试通过；正常键鼠操作待测 |
| 演出目的 | 淡入／头像支持阅读；开场没有目标引用时不显示目标框；临时效果结束后清理 | 技术框架与测试头像已检查；正式演出节奏等待正文后调整 |
| 操作恢复与失败 | 正常结束、跳过和对话中 Retry 恢复世界／角色；关闭帧无额外动作；Retry 不重读，新的 Play 会话可重新播放 | 自动整合通过；人工反复操作与实际路线待测 |
